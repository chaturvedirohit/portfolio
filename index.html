How I think

Four principles, each one earned on a real launch.

01

Evaluate before you ship

A 2,000-case golden dataset, a four-stage failure taxonomy and a precision and recall gate come before any model goes live.

02

Choose models on failure modes

I picked a slower, more accurate model for content safety because of how the faster one failed, not because of a published latency number.

03

Trace the error to its root

Most failures are few causes. One rule explained 59% of precision errors. One transliteration gap explained 71% of recall misses.

04

Build or buy with a framework

Five enterprise AI vendors compared before a line was written. The decision is documented so it can be revisited.

04

Product thinking, in long form

Decisions from production AI work, written as problem, approach and outcome.

Featured

Choosing the slower model for content safety

Published latency is not the same as how a model fails on your data.

Problem
Two candidate models for content-safety classification. The faster one looked better on paper.
Approach
Compared both on real failure modes from our own data.
Outcome
Shipped the slower, more accurate model.
Evaluation

One rule behind 59% of precision errors

A failure taxonomy turns a vague accuracy number into a fix list.

Problem
Precision errors and recall misses against a 2,000-case golden dataset.
Approach
A four-stage failure taxonomy to trace each failure to a root cause.
Outcome
One entity-association rule caused 59% of precision errors: value precision 95.1% to 98.0%. Indic transliteration variants caused 71% of recall misses: recall 97.6% once aliased.
Agent reliability

A hallucinated field that survived across turns

One bad value in context can quietly corrupt a whole session.

Problem
10 manually confirmed cases where a fabricated field persisted across conversation turns.
Approach
Redesigned the context architecture to re-validate every field against history before persisting it.
