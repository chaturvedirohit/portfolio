01

The problem

Manual validation could not keep up. 25,000+ new profiles arrive every day on a base of more than 5 million active users, and every one of them is somebody deciding whether to trust a stranger.

TODO: one line on what a bad profile actually costs the user.

THE REAL CONSTRAINT

Strictness and speed pull against each other. Every check that catches a bad profile also delays a real one, and a real user who waits is a real user who leaves.

02

What done looks like

Four things had to be true at the same time.

THROUGHPUT Every new profile screened the day it arrives, not in a queue.
PRECISION A real user is never blocked by a check that was only probably right.
RECALL Bad profiles are caught before anyone sees them.
COMPLETION The funnel still converts. Validation is not allowed to kill signup.

Which model for content safety, the faster one or the more accurate one?

CONTEXT Two candidate models. The faster one looked better on paper.
OPTIONS Published latency and benchmark scores, or how each one failed on our own data.
