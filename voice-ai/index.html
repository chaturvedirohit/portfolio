Why a voice layer

TODO: What users were doing before. Traditional touch interactions required navigating multi-step forms and complex filters, creating friction for users attempting to communicate preferences and search criteria quickly.

TODO: Why text alone was not enough. Text inputs suffered from high drop-off on mobile keypads, especially across regional languages and transliterated queries where spoken intent carries far richer context than typed keywords.

TODO: What made this worth building now. Recent advancements in low-latency speech pipelines, combined with reliable real-time agent orchestration, made natural spoken conversations technically viable and cost-effective at scale.

04

Decisions that mattered

Key trade-offs evaluated on live test sessions rather than benchmark claims.

DECISION 01

Streaming or batch transcription?

CONTEXT TODO: Need to balance turn-taking speed against transcription accuracy across variable mobile networks.
OPTIONS TODO: WebSocket streaming with partial hypotheses versus chunked audio uploads on silence detection.
CALL TODO: Selected streaming transcription with custom client-side voice activity detection.
WHY TODO: Reduced time-to-first-token by streaming tokens while the user was still completing natural sentence pauses.
DECISION 02

How long is the user willing to wait before we fill the silence?

CONTEXT TODO: Complex search queries and multi-system database lookups introduced dead air during complex turns.
OPTIONS TODO: Complete silence until full response versus conversational acoustic filler cues versus immediate partial confirmations.
CALL TODO: Configured a dynamic acoustic filler policy triggering after a strict latency threshold.
WHY TODO: User drop-offs increased sharply if dead air exceeded expectations, whereas brief verbal acknowledgement held user attention.
DECISION 03

What happens when the model is not confident?

CONTEXT TODO: Ambiguous names, garbled phone audio, or overlapping speakers resulted in low-confidence model extractions.
OPTIONS TODO: Best-effort guessing with implicit confirmation versus explicit clarification question versus immediate fallback.
CALL TODO: Explicit targeted disambiguation prompt isolating only the unclear entity.
WHY TODO: Guessing created downstream session corruption, while targeted reprompting resolved ambiguity in over 85% of cases.
DECISION 04

Build the orchestration layer or buy it?

CONTEXT TODO: Evaluated third-party voice agent platforms against proprietary domain routing and compliance rules.
OPTIONS TODO: Off-the-shelf voice SaaS provider versus building an in-house orchestration layer on raw model APIs.
CALL TODO: Built the core orchestration layer in-house while integrating best-of-breed modular models.
WHY TODO: Retained full control over prompt engineering, state persistence, security guardrails, and model vendor swapping.
